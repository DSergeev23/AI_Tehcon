# Публикация новостей на Timeweb App Platform

## Где находятся данные

- Статьи хранятся в таблице Supabase `public.news`.
- Обложки хранятся в публичном Supabase Storage bucket `news-covers`. HTML содержит ссылки на эти изображения.
- Готовые страницы находятся в ветке `app-platform` **того же GitHub-репозитория**: `news/index.html`, `news/<slug>/index.html`, `data/news/news.json`, `news-sitemap.xml`.
- Timeweb App Platform обслуживает готовые файлы из этой ветки после деплоя. Сайт и новости доступны на одном техническом домене, а после подключения `ai-tehcon.ru` — на этом основном домене.

Отдельное хранилище страниц `news-pages` и Cloudflare Worker этой схеме не нужны. Bucket `news-pages` был создан для предыдущего варианта и пока оставлен в Supabase как архив; текущий workflow его не обновляет. Обложки `news-covers` удалять нельзя.

## Что происходит автоматически

1. Изменения кода в `main` запускают `.github/workflows/publish-app-platform.yml`: он собирает React через `npm run build`, добавляет текущие новости в `dist`, публикует готовые файлы в `app-platform` и запускает деплой Timeweb.
2. Каждый час в 13 минут по UTC (в Москве — в 13 минут каждого часа) `.github/workflows/sync-news.yml` читает опубликованные статьи из Supabase. GitHub может запустить расписание с задержкой.
3. Если состав или данные опубликованных статей не изменились, workflow завершается без коммита и без деплоя.
4. Если новости изменились, workflow генерирует только их HTML, JSON и sitemap; обновляет только эти файлы в `app-platform` и запускает деплой Timeweb по новому коммиту. `npm ci` и `npm run build` не выполняются. CSS/JS сайта остаются прежними.
5. Timeweb берет новый снимок ветки и начинает отдавать обновленные новости. До успешного завершения этого деплоя новая статья на сайте не появится. При снятии статьи с публикации ее HTML удаляется из ветки при очередном запуске.

Репозиторий подключен к Timeweb **по URL**; такой способ не дает автодеплой по push. Поэтому вызов API Timeweb после изменения новостей обязателен. Это деплой готовых файлов, а не повторная сборка React. При обычном изменении кода тот же API вызывает основной workflow.

## Проверка и запуск

1. На GitHub откройте [репозиторий](https://github.com/DSergeev23/AI_Tehcon) → **Settings → Secrets and variables → Actions**. В **Variables** должны существовать `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `TIMEWEB_APP_ID`; в **Secrets** — `TIMEWEB_CLOUD_TOKEN`. Значения секретов в интерфейсе не показываются. S3-ключи для нового workflow не нужны.
2. Откройте **Actions → Publish news to Timeweb App Platform → Run workflow** и выберите `main`. Дождитесь завершения запуска со статусом Success. При ошибке откройте лог шага, на котором остановился запуск.
3. В **Code** переключитесь с `main` на `app-platform`. Проверьте наличие `news/index.html`, `data/news/news.json`, `news-sitemap.xml` и папок отдельных статей. Если статьи в Supabase не изменились, нового коммита не будет: это нормальный результат.
4. В Timeweb Cloud откройте **App Platform → приложение AI TehCon → Деплои**. Новый деплой появляется только после коммита с изменившимися новостями. Дождитесь успешного статуса.
5. Откройте [список новостей на техническом домене](https://dsergeev23-ai-tehcon-b981.twc1.net/news/) и конкретную статью. В исходном HTML статьи проверьте ее заголовок и canonical. Убедитесь, что адрес остается доменом Timeweb. После привязки `ai-tehcon.ru` аналогичные адреса будут на основном домене.

Для проверки именно обновления создайте или отредактируйте тестовую **опубликованную** статью в Supabase и запустите workflow вручную. После успешного деплоя убедитесь, что изменение видно на техническом домене. Не публикуйте фиктивную статью на основном домене; используйте реальный материал или верните изменение после проверки.

## Подключение основного домена

Домен остается зарегистрированным в Reg.ru. В Timeweb Cloud откройте приложение → **Настройки → Домены → Редактировать → Внешний домен**, укажите `ai-tehcon.ru` и сохраните. Timeweb покажет нужную A-запись. В DNS-панели, которая сейчас обслуживает домен, измените только записи сайта по подсказке Timeweb; почтовые MX/TXT-записи сохраните. После обновления DNS Timeweb выпустит SSL. Переадресация на Supabase или Cloudflare не требуется.

**Перед переключением DNS:** проверьте обработку формы заявок. Старый `/api/contact.php` не исполняется в статическом App Platform. Также проверьте почту, новости, изображения, sitemap и основной сайт. Старый cron в Timeweb Bitrix отключите только после проверки новой почасовой публикации и основного домена.

У трех опубликованных статей ранее обнаружены пути `test-news/cover.webp` к отсутствующей обложке: `anthropic-claude-frontier-academy-engineers`, `atlassian-openai-rovo-enterprise-context`, `chatgpt-audio-uploads-transcription`. Для них нужно загрузить реальные изображения в `news-covers` и обновить `cover_image_path` в Supabase.
