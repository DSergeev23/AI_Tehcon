# Переезд новостей на App Platform и GitHub Actions

Этот порядок сохраняет адреса `/news/...` и индексируемый HTML. Новости и фотографии остаются в Supabase. Почасовая публикация не вызывает сборку или деплой App Platform. Технический домен Timeweb получает снимок новостей при очередном деплое сайта.

**Состояние на 11 ноября 2026 года:** проект Supabase проверен, bucket `news-pages` уже создан и включен как публичный. Bucket `news-covers` содержит 34 файла; в таблице есть 24 опубликованные статьи. Для трех статей путь ведет к отсутствующему `test-news/cover.webp` (список ниже). `news-pages` пока пуст: GitHub Actions и Cloudflare еще не подключены. Не создавайте bucket повторно.

Работа разделена на две части. Разделы 1–4 запускают новости на техническом домене и наполняют Supabase. Разделы 5–6 подключают основной домен. Не меняйте DNS, пока не работает прием заявок: текущий `/api/contact.php` на статическом App Platform не исполняется.

## 1. Подготовить Supabase

1. Откройте [панель Supabase](https://supabase.com/dashboard/projects) и выберите проект **AI Tehcon**. Проверьте, что адрес страницы содержит `ngnpumsmxqvtkwcenbtu`: это нужный проект.
2. В левом меню нажмите **Storage**. В списке bucket должны быть `news-covers` и **уже созданный** `news-pages`. В `news-covers` лежат обложки: не переносите и не удаляйте их. В `news-pages` пока нет файлов — это ожидаемо до первого запуска cron.
3. В разделе Storage откройте **Configuration → S3** (если видите пункт **S3 Configuration**, это та же страница). Если протокол выключен, включите его. В блоке **Access keys** создайте новую пару для GitHub Actions. Имя, если предлагается, можно указать `ai-tehcon-news-github-actions`.
4. Сохраните показанные **Access Key ID** и **Secret Access Key** в надежном временном месте. Secret Access Key может показываться только при создании. Здесь же скопируйте **Endpoint** и **Region**. Для данного проекта ожидаемый регион `eu-west-1`; endpoint должен относиться к `ngnpumsmxqvtkwcenbtu` и заканчиваться на `/storage/v1/s3`. При расхождении используйте значения из панели.
5. В левом меню откройте **Project Settings → API Keys**. В секции publishable keys найдите действующий ключ `sb_publishable_...` (текущий ключ заканчивается на `mdUu`) и скопируйте его. Ключ `service_role`, secret key или пароль базы для чтения новостей не нужны.

S3-ключи имеют полный доступ к Storage проекта, включая `news-covers`, поэтому поместите их только в GitHub Actions Secrets. Не отправляйте их в чат и не сохраняйте в репозитории. Интеграция Supabase в Codex умеет читать базу и создавать bucket через SQL, но не управляет S3 Configuration и не выдает S3 access keys; эти действия выполняются в панели Supabase.

## 2. Добавить настройки GitHub Actions

1. Откройте [репозиторий GitHub](https://github.com/DSergeev23/AI_Tehcon).
2. В верхней строке нажмите **Settings**. Если вкладка скрыта, откройте меню с дополнительными вкладками и выберите Settings.
3. В левом меню найдите **Secrets and variables**, раскройте его и нажмите **Actions**. Вы попадете на страницу настроек для GitHub Actions. Не открывайте **Codespaces** или **Dependabot**: это другие наборы секретов.
4. Откройте вкладку **Variables**. Нажмите **New repository variable**. Для каждой строки таблицы ниже вводите `Name` и `Value`, затем нажимайте **Add variable** и возвращайтесь к списку Variables.

Вкладка **Variables**, кнопка **New repository variable**:

| Name | Value |
| --- | --- |
| `SUPABASE_URL` | `https://ngnpumsmxqvtkwcenbtu.supabase.co` |
| `SUPABASE_PUBLISHABLE_KEY` | ключ `sb_publishable_...` из Supabase |
| `SUPABASE_S3_ENDPOINT` | точный HTTPS endpoint из Supabase S3 Configuration; ожидается `https://ngnpumsmxqvtkwcenbtu.storage.supabase.co/storage/v1/s3` |
| `SUPABASE_S3_REGION` | точный регион из Supabase S3 Configuration; ожидается `eu-west-1` |

5. Откройте соседнюю вкладку **Secrets**. Нажмите **New repository secret**. По одному создайте два секрета ниже: заполните `Name`, вставьте `Secret`, нажмите **Add secret**. После сохранения GitHub не покажет значение еще раз — в списке видны только имена.

| Name | Value |
| --- | --- |
| `SUPABASE_S3_ACCESS_KEY_ID` | Access Key ID из Supabase S3 |
| `SUPABASE_S3_SECRET_ACCESS_KEY` | Secret Access Key из Supabase S3 |

6. Проверьте, что на странице перечислены **четыре Variables и два Secrets** с точными именами из таблиц. Регистр букв важен. Не вставляйте значения ключей в чат, issue, workflow или код.

## 3. Обновить технический сайт

1. После сохранения GitHub Variables и Secrets дайте Codex отдельное разрешение на commit и push подготовленных файлов в `main`. Правило проекта `AGENTS.md` запрещает делать commit и push без такого разрешения. Публиковать раньше настройки Variables не стоит: сборка завершится ошибкой из-за отсутствующих значений.
2. После push откройте [Actions](https://github.com/DSergeev23/AI_Tehcon/actions). В левом списке нажмите **Publish static site to Timeweb App Platform**. В центре появится новый запуск. Нажмите на него, затем на задачу **publish**.
3. Пройдите по шагам задачи: **Build site** и **Include current news in the static site** должны быть зелеными. В логе шага с новостями ожидается положительное число `articles` (на 11 ноября было 24). Не копируйте логи с ключами в публичный issue.
4. Вернитесь на вкладку **Code** репозитория. В переключателе веток над списком файлов вместо `main` выберите `app-platform`. Откройте `news/index.html`, `data/news/news.json` и `news-sitemap.xml`. В JSON поле `articles` должно содержать статьи, а `generatedAt` — дату вместо `null`.
5. В Timeweb Cloud откройте **App Platform → приложение AI Tehcon → Деплои**. Убедитесь, что деплой ветки `app-platform` завершился успешно. Если GitHub workflow не запустил деплой через API, нажмите ручной запуск деплоя в панели Timeweb для последнего коммита этой ветки.
6. Откройте [новости на техническом домене](https://dsergeev23-ai-tehcon-b981.twc1.net/news/) и [JSON новостей](https://dsergeev23-ai-tehcon-b981.twc1.net/data/news/news.json). На странице должны быть карточки; в JSON — непустой массив `articles`. Откройте любую карточку и проверьте обложку.

Это снимок для технического домена. Новая новость будет появляться на основном домене через шаги ниже, без нового деплоя.

## 4. Запустить почасовую публикацию

1. После успешного workflow **Publish static site to Timeweb App Platform** синхронизация новостей запускается автоматически. Для проверки или внеочередной публикации откройте [Actions](https://github.com/DSergeev23/AI_Tehcon/actions). В левом списке выберите **Publish news without App Platform deployment**.
2. Если автоматический запуск уже идет, откройте его; второй запуск не нужен. Если нужен ручной запуск, справа нажмите **Run workflow**, оставьте ветку `main` и подтвердите **Run workflow**. Затем откройте появившийся запуск и задачу **publish**. Все ее шаги должны стать зелеными. Workflow скачает оболочку уже работающего технического домена Timeweb, создаст новости и загрузит их в Storage. Поэтому ссылки на CSS/JS будут соответствовать текущему деплою, даже если следующий деплой сайта еще идет.
3. Откройте Supabase → проект **AI Tehcon** → **Storage → news-pages**. Внутри должны появиться папка `news` (ее `index.html` и папки отдельных статей), папка `data/news` с `news.json` и файл `news-sitemap.xml`.
4. В новой вкладке откройте [публичный JSON](https://ngnpumsmxqvtkwcenbtu.supabase.co/storage/v1/object/public/news-pages/data/news/news.json). Ищите `"articles": [` и `"generatedAt"`: список должен быть непустым. Затем откройте [сгенерированную HTML-страницу](https://ngnpumsmxqvtkwcenbtu.supabase.co/storage/v1/object/public/news-pages/news/index.html): должны быть видны новости.
5. Сравните время нового `generatedAt` с моментом запуска. При этом ветка `app-platform` и история деплоев Timeweb не должны измениться. Это и есть проверка публикации без пересборки.
6. Дальше GitHub Actions запускает workflow каждый час на 13-й минуте. GitHub может задержать scheduled run; это не механизм публикации с гарантией ровно в 13 минут. Если нужно выпустить новость раньше, повторите ручной запуск из пункта 2.

Защита workflow останавливает публикацию при нуле видимых опубликованных статей, чтобы ошибка доступа к Supabase не очистила живые страницы.

## 5. Подготовить Cloudflare и домен

**Пока не выполнять:** в текущем коде формы контактов и партнеров обращаются к `/api/contact.php`. Статический App Platform не выполняет PHP, поэтому формы на техническом домене не принимают заявки. Сначала нужен отдельный обработчик и проверка обеих форм. Шаги ниже описывают сам перенос домена после этой проверки.

1. Откройте [Cloudflare Dashboard](https://dash.cloudflare.com/). Если домен еще не добавлен, выберите **Add a domain / Add site**, введите `ai-tehcon.ru` без `https://` и выберите доступный план. На экране проверки DNS-записей Cloudflare предложит автоматически найденные записи.
2. Перед нажатием подтверждения откройте текущую панель DNS у того провайдера, чьи NS сейчас обслуживают домен (это может быть Reg.ru или старый Timeweb). Сравните записи **по одной**: A/AAAA/CNAME для сайта и `www`, MX для почты, TXT с SPF, DKIM, DMARC и подтверждениями сервисов. Добавьте в Cloudflare все отсутствующие записи. На этом этапе A-запись сайта должна пока указывать на **старый** хостинг, чтобы переключение NS само по себе не меняло сайт. Для почтовых записей выключите проксирование: они должны быть **DNS only**.
3. Cloudflare покажет **два индивидуальных NS-адреса**. Скопируйте их. Откройте [личный кабинет Reg.ru](https://www.reg.ru/user/account) → **Домены** → `ai-tehcon.ru` → вкладка **Управление** → блок **DNS-серверы и управление зоной** → **Изменить**. Выберите вариант **Свой список DNS-серверов** и внесите оба NS из Cloudflare. Сохраните. Не используйте NS из примеров в документации: у каждого домена они свои.
4. Вернитесь в Cloudflare. Дождитесь статуса домена **Active**. Обычно ожидание связано с обновлением DNS и может занять до суток. Проверьте, что `https://ai-tehcon.ru/` все еще открывает старый сайт и что рабочая почта получает письма. Если Cloudflare не активируется, проверьте точность NS и старые DNSSEC DS-записи у регистратора.
5. Откройте [Timeweb Cloud](https://timeweb.cloud/my/apps) → **App Platform** → нужное приложение → **Настройки** → блок **Домены** → **Редактировать** → **Внешний домен**. Введите `ai-tehcon.ru` и сохраните. Запишите IP-адрес A-записи, показанный Timeweb для этого приложения: он понадобится в Cloudflare. Привязка домена запускает деплой Timeweb.
6. Только после проверки форм и успешной публикации новостей откройте Cloudflare → зона `ai-tehcon.ru` → **DNS → Records**. Найдите A-запись с именем `@` (или `ai-tehcon.ru`), измените ее значение на IP из Timeweb и сохраните. Если для корня есть старые A/AAAA-записи, которые теперь ведут на старый сервер, удалите или замените их: конфликтующие записи распределят посетителей между старым и новым сайтом.
7. Оставьте новую A-запись в режиме **DNS only** (серое облако), пока Timeweb не выпустит сертификат и `https://ai-tehcon.ru/` не откроется через App Platform. Затем включите **Proxied** (оранжевое облако). В Cloudflare **SSL/TLS → Overview** выберите **Full (strict)** после проверки сертификата Timeweb.
8. Если используется `www.ai-tehcon.ru`, решите, должен ли он перенаправлять на основной домен. Для него нужна отдельная DNS-запись и, если он обслуживается Timeweb, отдельная привязка в доменах приложения. Проверьте редирект и сертификат до отключения старого хостинга.

## 6. Включить Worker для прежних адресов новостей

1. Убедитесь, что шаг 4 уже загрузил файлы в `news-pages`, основной домен открывает Timeweb и его DNS-запись в Cloudflare имеет **оранжевое облако**. Без этого Worker route не сработает.
2. В [Cloudflare Dashboard](https://dash.cloudflare.com/) в меню аккаунта откройте **Workers & Pages** → **Create application** → **Create Worker**. Назовите его `ai-tehcon-news` и создайте. Если Cloudflare сначала предлагает шаблон кода, выберите простой Worker без Git-интеграции.
3. Откройте созданный Worker → **Edit code**. Удалите пример кода целиком, вставьте содержимое файла `cloudflare/news-router.js` из проекта и нажмите **Deploy**. Здесь не нужны S3-ключи: Worker только читает публичные файлы.
4. У Worker откройте **Settings → Variables and Secrets** → **Add**. Тип — обычная **Variable**, имя `SUPABASE_URL`, значение `https://ngnpumsmxqvtkwcenbtu.supabase.co`. Сохраните; если Cloudflare предлагает выпустить новую версию Worker, подтвердите публикацию. Это публичный URL, не секрет.
5. Затем откройте **Settings → Domains & Routes → Add → Route**. В поле Zone выберите `ai-tehcon.ru`, в Pattern введите `ai-tehcon.ru/news*`, сохраните. Повторите действие для `ai-tehcon.ru/data/news/news.json*` и `ai-tehcon.ru/news-sitemap.xml*`. В итоге в списке должны быть **три routes** одного Worker. Не добавляйте route `ai-tehcon.ru/*`: он отправит в Worker весь сайт.
6. В браузере откройте `https://ai-tehcon.ru/news/`. Адрес должен остаться на `ai-tehcon.ru`, а карточки появиться. Откройте любую статью и проверьте текст и обложку. Затем откройте `https://ai-tehcon.ru/data/news/news.json` и `https://ai-tehcon.ru/news-sitemap.xml`: они должны возвращать данные, не пустой стартовый файл и не HTML главной страницы.
7. Для SEO проверьте исходный код одной статьи: через меню браузера **Просмотреть исходный код страницы** найдите `<title>`, `<link rel="canonical" ...>` и заголовок статьи в HTML. При неверной настройке Worker App Platform может вернуть оболочку SPA вместо готовой статьи.
8. После успешной проверки зайдите в старый Timeweb Bitrix → раздел cron-заданий и отключите задачу, которая запускает `sync-news.php`. Старый хостинг отключайте только после проверки всего сайта, форм, изображений, sitemap и почты.

## Где хранятся фотографии и что происходит при новой публикации

Обложки остаются в `news-covers`. В таблице `public.news.cover_image_path` записан путь к файлу, например `generated/<job-id>/<name>.avif`. Генератор формирует публичную ссылку Supabase Storage и вставляет ее в карточку, статью, Open Graph и JSON. Bucket `news-pages` хранит текстовые результаты генерации; загружать туда фотографии не нужно.

Перед финальной проверкой обложек исправьте три опубликованные записи: `anthropic-claude-frontier-academy-engineers`, `atlassian-openai-rovo-enterprise-context`, `chatgpt-audio-uploads-transcription`. В каждой `cover_image_path = test-news/cover.webp`, но такого объекта нет в `news-covers`; соответствующих файлов с этими сюжетами в bucket тоже не найдено. Нужны подходящие обложки, загруженные в `news-covers`, и реальные пути к ним в этих трех строках. Не заменяйте их случайными изображениями других новостей.

Когда редактор переводит статью в `published` или наступает ее `published_at`, очередной почасовой запуск увидит ее, обновит HTML/JSON/sitemap в Supabase Storage, и Cloudflare начнет отдавать ее на основном домене. При этом GitHub не меняет ветку `app-platform` и не запускает Timeweb деплой. Если статья снята с публикации, workflow удалит ее HTML из `news-pages`; запрос вернет 404.
