OpenAI опубликовала тесты AI-моделей для переноса программ на COBOL

Автор: AI TehCon

OpenAI сообщила об улучшении результатов своих моделей в задачах переноса COBOL-программ и опубликовала отдельный тест для разработки на разных языках. Цифры получены в испытаниях компании и не означают готовности автоматически переносить действующие системы.

3 минут

19 октября OpenAI опубликовала результаты испытаний моделей на языках, для которых сравнительно мало обучающих материалов, включая COBOL, Fortran и Visual Basic. Один из тестов проверяет перенос COBOL-программ с сохранением их поведения. Это значимая задача для компаний со старым программным обеспечением: при переписывании кода важно сохранить заложенные в нём правила расчётов и обработки данных.

Что именно измеряла OpenAI

В тесте миграции модель переводила COBOL-программы на C++, Java, Kotlin, Python или Rust. Результат считался успешным, только если он проходил скрытые проверки с побайтовым совпадением наблюдаемого вывода. По данным OpenAI, GPT-6.1 Sol при низком уровне усилий рассуждения достигла точности 86,6% против 5,4% у GPT-5.6 Sol; при более высоком уровне результат GPT-6.1 Sol составил 97,9%. Это показатели на тестовом наборе компании, а не доля успешно завершённых проектов миграции.

OpenAI представила и MultiLangBench: модель должна создать совместимый с SQLite механизм работы с базой данных на одном из 20 языков. Компания сообщает о среднем результате GPT-6 Astra в 87,4% пройденных тестов против 26,8% у GPT-5.6 Sol. Код и устройство тестового набора опубликованы на GitHub, что позволяет изучить методику. Независимого воспроизведения заявленных результатов в использованных материалах нет.

Почему совпадение поведения важнее перевода строк

Программа может успешно собираться и при этом менять бизнес-результат. OpenAI приводит пример: COBOL может отбрасывать лишние десятичные знаки, если округление не задано явно; переписанная программа с автоматическим округлением выдаст другую сумму. Поэтому перед переносом корпоративной системы команде нужны контрольные входные данные, ожидаемые результаты, проверки интеграций и экспертиза людей, знающих предметную область.

Последние модели можно пробовать через API, но публикация не описывает готовый сервис автоматической миграции. Открытая методика MultiLangBench также не подтверждает результаты на конкретной кодовой базе компании. Практический следующий шаг — небольшой пилот на изолированном модуле с измерением доли совпавших результатов, стоимости исправлений и времени проверки.
